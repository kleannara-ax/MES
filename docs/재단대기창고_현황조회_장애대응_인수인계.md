# 재단대기창고 현황조회 장애 대응 인수인계서

## 1. 문서 목적

이 문서는 MES의 **재단대기창고 현황조회** 화면에서 다음 문제가 발생했을 때 원인을 찾고 안전하게 대응하기 위한 안내서입니다.

- 바코드가 재단대기창고 화면에 보이지 않는 경우
- 바코드는 보이지만 상세정보를 누르면 `작업지시 정보를 찾지 못했습니다.`가 표시되는 경우
- 취소한 과거 실적과 새로 등록한 실적이 함께 존재하는 경우
- SAP 확정 취소 인터페이스에서 `확정수량이 없음` 오류가 발생한 경우

SQL이나 MES 구조를 잘 모르는 담당자도 순서대로 확인할 수 있도록 작성했습니다.

## 2. 먼저 알아야 할 용어

| 용어 | 설명 | 대표 컬럼/값 |
|---|---|---|
| 개별 바코드 | 생산된 롤 또는 제품 한 건을 식별하는 번호 | `IND_BCD` |
| 생산오더 | SAP 생산오더 번호 | `ORDER_NO`, `AUFNR` |
| 작업지시 | MES에서 사용하는 작업지시 번호 | `WRK_ORDR_NO`, `WRK_ORDR_SEQNO` |
| LOT | 생산 LOT 번호 | `LOT_NO` |
| 저장위치 | SAP/MES의 큰 창고 구분 | `STOR_LOC_CD`, 재단대기창고는 `2700` |
| 로케이션 | 창고 안의 세부 위치 | `LOC_CD`, 예: `MR41`, `MR45` |
| SAP 확정번호 | SAP 생산실적 확정 번호 | `RUECK`, MES에서는 `SDOC_NO` |
| SAP 확정카운터 | 같은 확정번호 안의 처리 순번 | `RMZHL`, MES에서는 `SDOC_SEQNO` |
| 취소 여부 | MES 실적이 취소되었는지 표시 | `CNL_YN`, `Y`이면 취소 |
| 재고수량 | 현재 MES 재고수량 | `STCK_QTY` |
| 재고상태 | 현재 재고 상태 | `STCK_STA`, 정상 대기는 보통 `00` |
| 삭제 표시 | 재고가 논리적으로 삭제되었는지 표시 | `DLFL`, `Y`이면 삭제 처리 |

## 4. 화면에 바코드가 표시되는 기본 조건

재단대기창고 화면은 `TB_INV001`의 모든 데이터를 보여 주는 화면이 아닙니다. 대략 다음 조건을 만족하는 재고만 표시합니다.

```sql
WERKS       = 'P100'
STOR_LOC_CD = '2700'
STCK_QTY    > 0
STCK_STA    = '00'
```

그리고 `LOC_CD`가 `MR01`부터 `MR45`까지인 데이터를 각 로케이션 열에 배치합니다.

`MR41`은 별도 업무 조건이 있는 특수 코드가 아닙니다. `MR01~MR45` 중 하나의 로케이션 열입니다. 코드에서 `MR41`만을 대상으로 하는 별도 `IF` 또는 `WHERE` 조건은 확인되지 않았습니다.

### 화면과 동일한 기본 조회

```sql
SELECT
    I.WERKS,
    I.IND_BCD,
    I.LOT_NO,
    I.ORDER_NO,
    I.MATNR,
    I.WRK_ORDR_NO,
    I.WRK_ORDR_SEQNO,
    I.STOR_LOC_CD,
    I.LOC_CD,
    L.LOC_NM,
    I.STCK_QTY,
    I.STCK_STA,
    I.DLFL,
    I.IN_MR_YN,
    I.MR_WH_YN
FROM KNRAMES.TB_INV001 I
LEFT JOIN KNRAMES.TB_MAS028 L
       ON L.WERKS = I.WERKS
      AND L.STOR_LOC_CD = I.STOR_LOC_CD
      AND L.LOC_CD = I.LOC_CD
WHERE I.WERKS = 'P100'
  AND I.STOR_LOC_CD = '2700'
  AND I.STCK_QTY > 0
  AND I.STCK_STA = '00'
ORDER BY I.LOC_CD, I.IND_BCD;
```

특정 바코드를 확인할 때는 아래 조건을 추가합니다.

```sql
AND I.IND_BCD = '확인할 바코드'
```

MR41만 확인할 때는 아래 조건을 추가합니다.

```sql
AND I.LOC_CD = 'MR41'
```

## 5. 증상별 원인 구분

## 5.1 목록에도 바코드가 보이지 않는 경우

다음 중 하나일 가능성이 높습니다.

1. `TB_INV001`에 바코드가 없습니다.
2. 저장위치가 `2700`이 아닙니다.
3. 재고수량 `STCK_QTY`가 0 이하입니다.
4. 재고상태 `STCK_STA`가 `00`이 아닙니다.
5. 로케이션 `LOC_CD`가 `MR01~MR45` 범위가 아니거나 값이 없습니다.
6. 플랜트 `WERKS`가 화면에서 조회하는 플랜트와 다릅니다.
7. 화면의 추가 검색조건에 의해 제외되었습니다.

### 확인 쿼리

```sql
SELECT
    WERKS,
    IND_BCD,
    LOT_NO,
    ORDER_NO,
    STOR_LOC_CD,
    LOC_CD,
    STCK_QTY,
    STCK_STA,
    DLFL,
    IN_MR_YN,
    MR_WH_YN
FROM KNRAMES.TB_INV001
WHERE IND_BCD = '확인할 바코드';
```

결과를 화면 조건과 한 항목씩 비교합니다.

---

## 5.2 목록에는 보이지만 상세정보가 열리지 않는 경우

목록조회와 상세조회는 서로 다른 조건을 사용합니다.

- 목록은 주로 `TB_INV001`의 재고상태를 봅니다.
- 상세정보는 `TB_WRK002`, `TB_SCH016`, `TB_SCH017`의 작업실적과 작업지시를 봅니다.

따라서 재고에는 남아 있지만 생산실적이 취소된 바코드는 목록에는 표시되고 상세조회에서는 제외될 수 있습니다.

상세조회 프로시저의 핵심 조건은 다음과 같습니다.

```sql
AND W002.WERKS = P_WERKS
AND W002.IND_BCD = P_IND_BCD
AND W002.WRK_ORDR_NO = P_WRK_ORDR_NO
AND W002.WRK_ORDR_SEQNO = P_WRK_ORDR_SEQNO
AND NVL(W002.CNL_YN, 'N') = 'N'
AND S017.USE_YN = 'Y'
```

특히 `TB_WRK002.CNL_YN='Y'`이면 취소된 실적이므로 상세조회 대상에서 제외됩니다. 조건을 만족하는 행이 없으면 다음 메시지가 표시됩니다.

```text
작업지시 정보를 찾지 못했습니다.
```

### 상세조회 가능 여부 확인 쿼리

```sql
SELECT
    W002.IND_BCD,
    W002.WRK_ORDR_NO,
    W002.WRK_ORDR_SEQNO,
    W002.ORDER_NO,
    W002.LOT_NO,
    W002.CNL_YN,
    W002.CNL_RMK,
    S017.USE_YN,
    CASE
        WHEN NVL(W002.CNL_YN, 'N') = 'Y' THEN '취소 실적이므로 상세조회 제외'
        WHEN S016.WRK_ORDR_NO IS NULL THEN '작업지시 없음'
        WHEN S017.PRE_ORDER_NO IS NULL THEN '후속 작업지시 없음'
        WHEN NVL(S017.USE_YN, 'N') <> 'Y' THEN '후속 작업지시 미사용'
        ELSE '상세조회 가능'
    END AS CHECK_RESULT
FROM KNRAMES.TB_WRK002 W002
LEFT JOIN KNRAMES.TB_SCH016 S016
       ON S016.WERKS = W002.WERKS
      AND S016.WRK_ORDR_NO = W002.WRK_ORDR_NO
      AND S016.WRK_ORDR_SEQNO = W002.WRK_ORDR_SEQNO
LEFT JOIN KNRAMES.TB_SCH017 S017
       ON S017.WERKS = S016.WERKS
      AND S017.PRE_ORDER_NO = S016.ORDER_NO
      AND S017.USE_YN = 'Y'
WHERE W002.WERKS = 'P100'
  AND W002.IND_BCD = '확인할 바코드';
```

## 6. 이번 장애 사례

### 기존 실적과 신규 실적

| 작업오더 | LOT | 기존 바코드 | 기존 확정 | 기존 상태 | 신규 바코드 | 신규 확정 | 신규 상태 |
|---|---|---|---|---|---|---|---|
| `1112882924` | `6910M30393` | `26910M0403` | `0013129111 / 00000001` | 취소 | `26910M0423` | `0013129111 / 00000003` | 정상 후보 |
| `1112882923` | `6910M30395` | `26910M0405` | `0013129110 / 00000001` | 취소 | `26910M0425` | `0013129110 / 00000003` | 정상 후보 |

기존 바코드는 `TB_WRK002.CNL_YN='Y'`로 취소 처리되어 있습니다. 그러나 `TB_INV001`에 가용재고 형태로 남아 있으면 목록에는 계속 표시됩니다. 사용자가 이 기존 바코드의 상세정보를 누르면 상세조회 조건인 `CNL_YN='N'`을 만족하지 못하여 오류 메시지가 발생합니다.

신규 바코드 `26910M0423`, `26910M0425`는 번호 모양만 보고 추측한 것이 아닙니다. 기존 바코드와 다음 값이 같고, 기존 실적 취소 후 등록시간이 더 늦으며, 취소되지 않았기 때문에 후속 실적으로 판단했습니다.

- 동일 `ORDER_NO`
- 동일 `LOT_NO`
- 동일 `WRK_ORDR_NO`, `WRK_ORDR_SEQNO`
- 동일 품목
- 동일 실적수량과 길이
- 동일 SAP 확정번호의 후속 확정카운터

### 기존 바코드로 후속 실적 찾기

```sql
WITH OLD_DATA AS (
    SELECT
        WERKS,
        IND_BCD,
        ORDER_NO,
        LOT_NO,
        WRK_ORDR_NO,
        WRK_ORDR_SEQNO,
        REGDATE
    FROM KNRAMES.TB_WRK002
    WHERE WERKS = 'P100'
      AND IND_BCD IN ('26910M0403', '26910M0405')
)
SELECT
    O.IND_BCD AS ORIGINAL_IND_BCD,
    W.IND_BCD,
    CASE
        WHEN W.IND_BCD = O.IND_BCD THEN '기존 실적'
        WHEN W.REGDATE > O.REGDATE
         AND NVL(W.CNL_YN, 'N') = 'N' THEN '후속 정상 실적 후보'
        WHEN NVL(W.CNL_YN, 'N') = 'Y' THEN '취소 실적'
        ELSE '관련 실적'
    END AS PRFM_TYPE,
    W.ORDER_NO,
    W.LOT_NO,
    W.WRK_ORDR_NO,
    W.WRK_ORDR_SEQNO,
    W.PRFM_QTY,
    W.ROLLCNT,
    W.CNL_YN,
    W.SDOC_NO AS RUECK,
    W.SDOC_SEQNO AS RMZHL,
    W.REGDATE
FROM OLD_DATA O
JOIN KNRAMES.TB_WRK002 W
  ON W.WERKS = O.WERKS
 AND W.ORDER_NO = O.ORDER_NO
 AND W.LOT_NO = O.LOT_NO
 AND W.WRK_ORDR_NO = O.WRK_ORDR_NO
 AND W.WRK_ORDR_SEQNO = O.WRK_ORDR_SEQNO
ORDER BY O.IND_BCD, W.REGDATE;
```

## 7. SAP 취소 인터페이스 오류의 의미

생산실적 확정 취소 인터페이스는 다음과 같습니다.

```text
인터페이스 ID : MES_IF_129
테이블        : TB_IFS007
문서 Prefix   : MIF129
처리 프로시저 : SP_IF_PUT_IFS007
```

이번 사례에서는 다음 오류가 반환되었습니다.

```text
1112882924 확정수량이 없음
1112882923 확정수량이 없음
```

이 메시지는 MES에 생산수량이 없다는 뜻이 아닙니다. SAP가 취소 요청을 처리하는 시점에 지정한 `RUECK + RMZHL`에서 취소할 수 있는 확정수량을 찾지 못했다는 뜻입니다.

가능한 원인은 다음과 같습니다.

1. SAP에서 해당 확정이 이미 취소되었습니다.
2. 다른 경로 또는 수작업으로 먼저 취소되었습니다.
3. MES가 보낸 확정카운터와 SAP의 실제 취소 대상 카운터가 다릅니다.
4. 최초 실적 확정이 정상 완료되지 않았는데 취소 요청이 생성되었습니다.
5. SAP에서 확인되는 잔여 확정수량과 MES의 취소수량이 다릅니다.

이번 사례의 `TB_IFS007`에는 동일 `RUECK + RMZHL`의 중복 행은 확인되지 않았습니다. 그러므로 단순히 MES가 같은 행을 두 번 생성했다고 단정하면 안 됩니다.

### 취소 인터페이스 조회

```sql
SELECT
    RUECK,
    RMZHL,
    AUFNR,
    LOTNO,
    ROLLCNT,
    MDOCNO,
    MDOCSEQ,
    ZRESULT,
    ZMESSAGE,
    MAKE_DATE,
    ZRESULT_DATE,
    SEND_YN,
    IF_MES_KEY
FROM KNRAMES.TB_IFS007
WHERE RUECK IN ('0013129110', '0013129111')
ORDER BY RUECK, RMZHL, MAKE_DATE;
```

주의할 점은 `MAKE_DATE`가 취소 요청 생성시간이고 `ZRESULT_DATE`가 SAP 응답 반영시간이라는 것입니다. 두 시간이 며칠씩 차이 나면 요청 생성과 실제 SAP 처리 사이에 지연이 있었는지 확인해야 합니다.

## 8. 신규 실적이 정상인지 확인하는 방법

## 8.1 생산실적 원본 확인

```sql
SELECT
    W.IND_BCD,
    W.ORDER_NO,
    W.LOT_NO,
    W.WRK_ORDR_NO,
    W.WRK_ORDR_SEQNO,
    W.MATNR,
    W.PRFM_QTY,
    W.ROLLCNT,
    W.WGT,
    W.CNL_YN,
    W.CNL_RMK,
    W.PRFM_GTHR_YN,
    W.DOC_NO,
    W.DOC_SEQNO,
    W.SDOC_NO,
    W.SDOC_SEQNO,
    W.REGDATE,
    W.UPDDATE
FROM KNRAMES.TB_WRK002 W
WHERE W.WERKS = 'P100'
  AND W.IND_BCD IN ('26910M0423', '26910M0425')
ORDER BY W.IND_BCD;
```

정상 후보 기준:

- `CNL_YN`이 `NULL` 또는 `N`
- `PRFM_GTHR_YN='Y'`
- `DOC_NO`가 존재
- `SDOC_NO`, `SDOC_SEQNO`에 SAP 확정번호와 카운터가 존재

## 8.2 MES_IF_126 생산실적 확정 확인

`MES_IF_126`은 `TB_IFS004`를 사용합니다.

```sql
SELECT
    I.AUFNR,
    I.MRLOT,
    I.WERKS,
    I.WORKCENTERCODE,
    I.MROLLCNT,
    I.RBRGEW,
    I.CONFM,
    I.MDOCNO,
    I.MDOCSEQ,
    I.RUECK,
    I.RMZHL,
    I.ZRESULT,
    I.ZMESSAGE,
    I.MAKE_DATE,
    I.ZRESULT_DATE,
    I.IF_MES_KEY
FROM KNRAMES.TB_IFS004 I
WHERE I.MDOCNO IN (
    'MIF12626091022445722',
    'MIF12626091022445728'
)
ORDER BY I.MDOCNO, I.MDOCSEQ;
```

정상 기준:

- `ZRESULT='S'`
- `RUECK`, `RMZHL`이 비어 있지 않음
- `TB_WRK002.SDOC_NO/SDOC_SEQNO`와 동일
- `AUFNR`, LOT, 수량이 생산실적과 일치

## 8.3 MES_IF_130 제품입고 확인

```sql
SELECT *
FROM KNRAMES.TB_IFS008
WHERE MDOCNO IN (
    'MIF13026091022445723',
    'MIF13026091022445729'
```

정상 기준:

- `ZRESULT='S'`
- SAP 자재문서번호와 연도가 존재
- `TB_WRK021`의 제품입고 행에 기록된 번호와 일치

```sql
    SDOC_SEQNO,

    REGDATE,

FROM KNRAMES.TB_WRK021
WHERE WERKS = 'P100'
  AND IND_BCD IN ('26910M0423', '26910M0425')
```

## 9. 구 실적과 신규 실적의 재고 중복 확인

이 검사는 반드시 해야 합니다. 취소된 기존 바코드와 새 바코드가 모두 가용재고로 남아 있으면 MES 재고가 중복됩니다.

```sql
SELECT
    I.ORDER_NO,
    I.LOT_NO,
    I.IND_BCD,
    I.STOR_LOC_CD,
    I.LOC_CD,
    I.STCK_QTY,
    I.STCK_STA,
    I.DLFL,
    W.PRFM_QTY,
    W.CNL_YN,
    W.CNL_RMK,
    W.SDOC_NO,
    W.SDOC_SEQNO
FROM KNRAMES.TB_INV001 I
LEFT JOIN KNRAMES.TB_WRK002 W
       ON W.WERKS = I.WERKS
      AND W.IND_BCD = I.IND_BCD
WHERE I.WERKS = 'P100'
  AND I.IND_BCD IN (
      '26910M0403',
      '26910M0405',
      '26910M0423',
      '26910M0425'
  )
ORDER BY I.ORDER_NO, I.IND_BCD;
```

정상적인 최종 모습은 다음과 같습니다.

```text
기존 바코드 0403/0405
  TB_WRK002.CNL_YN = Y
  TB_INV001.STCK_QTY = 0 또는 DLFL = Y

신규 바코드 0423/0425
  TB_WRK002.CNL_YN = NULL 또는 N
  TB_INV001.STCK_QTY > 0
  TB_INV001.STCK_STA = 00
  TB_INV001.DLFL = NULL 또는 N
```

기존 바코드와 신규 바코드가 모두 `STCK_QTY > 0`, `STCK_STA='00'`이면 정합성 오류를 의심해야 합니다.

## 10. 대응 절차

## 10.1 절대 바로 수정하지 말아야 하는 값

원인을 확인하지 않은 상태에서 다음 작업을 하면 안 됩니다.

- `TB_WRK002.CNL_YN`을 임의로 `Y`에서 `N`으로 변경
- `TB_IFS007.ZRESULT`를 `N`으로 바꾸어 무조건 재전송
- `TB_INV001` 행을 바로 삭제
- 신규 정상 바코드의 재고수량을 0으로 변경
- SAP 상태 확인 없이 확정번호나 확정카운터 변경

이런 수정은 화면만 일시적으로 정상처럼 보이게 만들 수 있지만 SAP 실적 또는 실재고와 차이를 더 크게 만들 수 있습니다.

## 10.2 안전한 처리 순서

1. 문제 바코드의 `TB_INV001` 상태를 확인합니다.
2. `TB_WRK002.CNL_YN`과 작업지시 연결 상태를 확인합니다.
3. 같은 작업오더·LOT의 후속 실적을 찾습니다.
4. 신규 실적의 `TB_IFS004` 결과가 성공인지 확인합니다.
5. 신규 입고의 `TB_IFS008` 결과가 성공인지 확인합니다.
6. SAP 담당자에게 기존 `RUECK/RMZHL`의 현재 상태를 확인합니다.
7. 기존 확정이 SAP에서 이미 취소되었다면 기존 바코드의 잔존 재고를 정합성 처리합니다.
8. `TB_IFS007` 오류 건은 운영 관례에 따라 재전송 제외 또는 종료 처리합니다.
9. 화면을 새로 조회하여 기존 바코드가 사라지고 신규 바코드만 남는지 확인합니다.
10. 신규 바코드 상세정보가 정상적으로 열리는지 확인합니다.

## 10.3 DB 정합성 보정 시 원칙

DB 직접 수정은 운영 DBA와 업무 담당자의 승인을 받은 후 수행합니다. 특히 다음을 지켜야 합니다.

- SAP 실제 상태를 먼저 확인합니다.
- 수정 대상 바코드를 정확히 지정합니다.
- 수정 전 원본 행을 별도 조회 결과로 보관합니다.
- 한 트랜잭션에서 처리하고 결과를 확인한 뒤 커밋합니다.
- 예상 건수와 다르면 롤백합니다.
- `TB_INV001` 이력 트리거가 정상 동작하는지 확인합니다.
- 신규 정상 바코드는 수정 대상에서 제외합니다.

운영환경에서 사용할 UPDATE 문은 시스템별 운영 절차와 승인 내용을 반영하여 DBA가 작성하거나 검토해야 합니다. 이 문서에는 실수로 실행하는 일을 막기 위해 확정 UPDATE 문을 제공하지 않습니다.

## 13. 최종 점검표

아래 항목을 모두 확인해야 조치 완료로 판단합니다.

- [ ] 신규 바코드의 `TB_WRK002.CNL_YN`이 `NULL` 또는 `N`이다.

- [ ] 기존 취소 바코드는 가용재고에서 제외되었다.
- [ ] 구 바코드와 신규 바코드가 이중재고로 잡히지 않는다.
- [ ] 재단대기창고 화면에는 정상 바코드만 표시된다.
- [ ] 신규 바코드의 상세정보가 정상적으로 열린다.
- [ ] SAP와 MES의 수량·확정상태가 일치한다.

## 14. 한 줄 요약

> 재단대기창고 목록은 `TB_INV001`의 재고 조건으로 표시되고, 상세정보는 취소되지 않은 `TB_WRK002` 실적과 작업지시 조건으로 표시된다. 따라서 취소된 실적의 재고가 `TB_INV001`에 남아 있으면 목록에는 보이지만 상세정보는 열리지 않는다. SAP 확정·취소 상태와 신규 실적을 확인한 후 기존 잔존 재고를 안전하게 정합성 처리해야 한다.
